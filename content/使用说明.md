# 使用说明

本文覆盖项目的完整用法：环境准备、脚本、目录结构、文档编写约定，以及提交流程。

## 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | `>= 20.0.0` | 开发验证于 v22.23.3 |
| npm | 随 Node 附带 | 未强制锁版本 |

> Node 需支持 `--experimental-strip-types`，该能力自 20.6 起提供。低于此版本无法直接运行 TypeScript 源码。

## 安装

```bash
npm install
```

安装 201 个包，约 13 秒（使用 npmmirror 镜像）。

## 脚本一览

| 命令 | 作用 | 输出目录 |
| --- | --- | --- |
| `npm run docgen` | 扫描 `content/` 生成 HTML | `dist/` |
| `npm run typecheck` | 类型检查，不产出文件 | — |
| `npm run lint` | ESLint，含类型感知规则 | — |
| `npm run build` | 编译为 JS + `.d.ts` + sourcemap | `build/` |
| `npm run clean` | 清理两个产物目录 | — |

> `build/` 与 `dist/` 是两套独立产物，目录不重叠，`clean` 会一并删除。

### 两套 tsconfig 的分工

- `tsconfig.json`：开发期检查，`noEmit: true`，允许 `.ts` 后缀导入
- `tsconfig.build.json`：编译产物，关闭 `allowImportingTsExtensions`（与 emit 互斥），改用 `rewriteRelativeImportExtensions` 自动把 `./x.ts` 重写为 `./x.js`

源码统一写 `.ts` 扩展名导入，因此 `npm run docgen` 能用 Node 直接跑源码，无需预编译。

## 编写文档

在 `content/` 下新建 `.md` 即可，子目录会递归扫描并保留层级。

### Front-matter

```markdown
---
title: 使用说明
slug: usage
order: 3
---

# 正文一级标题
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 否 | 缺省时取文件名（去掉 `.md`） |
| `slug` | 否 | 指定 HTML 产物名，只允许字母数字与 `._-` |
| `order` | 否 | 索引页排序权重，升序；缺省排到末尾 |

### 中文文件名 + 英文产物名

源文件可以叫 `使用说明.md`，配合 `slug: usage` 生成 `usage.html`：

```text
content/使用说明.md  ──slug──▶  dist/usage.html
```

这样仓库里的文件名对中文读者友好，URL 里也不会出现 `%E4%BD%BF` 这类百分号编码。`slug` 缺失时直接沿用源文件名，产物名就会是中文，此时链接依然可用，只是 URL 编码较难看。

> `slug` 不允许包含 `/`，因此只能指定文件名，不能借此改变目录层级。

### 索引排序

`order` 生效，索引页按其升序排列：

| order | 文档 |
| --- | --- |
| 1 | 快速开始 |
| 2 | 架构说明 |
| 3 | 使用说明 |

order 相同则回退到中文路径序，保证多次构建输出一致。

### 标题层级决定目录

文档内的 `##` `###` 会被抽取成目录树，层级用栈还原，父节点通过缩进体现。

> **约定**：`src/toc.ts` 的 `slugify` 必须与 `rehype-slug` 行为对齐——小写、空格转连字符、去除标点、保留中日韩字符。改动其中一处时另一处要同步，否则目录锚点会全部失效。

### 索引页的跨页锚点

索引页会把各文档的目录内嵌到自己的页面里，因此锚点必须带文档路径前缀：

```text
✓ architecture.html#parse     正确，跨页指向
✗ #parse                      错误，索引页并无此锚点
```

## 排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 索引页目录点不动 | 锚点缺文档路径前缀 | 用 `renderTocMarkdown(nodes, doc.htmlPath, 1)` |
| `build/` 意外进了版本库 | `.gitignore` 写了行尾注释 | gitignore 不支持行尾注释，注释须独占一行 |
| `TS5096` 编译报错 | `allowImportingTsExtensions` 与 emit 互斥 | 编译配置改用 `rewriteRelativeImportExtensions` |
| `docgen` 跑完没输出 | 脚本误指向库模块 | 入口应是 `src/cli.ts` |

## Git 提交

### 配置身份

仓库级身份只写入本仓库的 `.git/config`，不影响其他项目：

```bash
cd /mnt/d/docs_lab
git config user.name "你的名字"
git config user.email "你的邮箱"
```

加 `--global` 则写入 `~/.gitconfig`，对名下所有仓库生效。

### 提交前检查

```bash
npm run typecheck && npm run lint && npm run docgen
git status --short          # 确认 node_modules / dist / build 均未纳入
```

### 提交

```bash
git add <具体文件>
git commit -m "feat: 新增使用说明文档"
```

只暂存需要提交的文件；`dist/` 与 `build/` 属生成物，应保持未跟踪状态。
